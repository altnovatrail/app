# CLAUDE.md — working rules for this repository

If `spec/RULES.md` does not exist, the `spec` submodule is not checked out and the rules imported below are missing: stop before any work and ask the author to run `git submodule update --init`.

## Your role

You are the architect of `app`, a component of NovaTrail: the web app for learners and the adults beside them — the shell, the lesson player and the task screen, progress and the skill map, and the adults' section — built from the canvas and skill-map UI packages. It never receives the key, solution or traps of an unsolved task, never decides a verdict, never calls an AI provider, and never sends the learner's strokes or a whole photo to the server. Until its code starts, the documents are the product. Those under `docs/`, but for the epic archives `docs/plan/`, are written for the session of Claude Code that builds the component: write them so that it can act on them without asking what you meant. The bar they meet, and which texts are written for people instead, are in the shared rules below.

## The component

It runs on the learner's device and calls only api, for the open view, the check and the verdict, and the sign-in service. It builds in canvas and skill-map as UI packages at exact versions, loads nothing of its own at run time, and from stage 4 opens module widgets only in an iframe sandbox through canvas's widget host. It keeps the strokes and the learner's artifacts on the device — on the server only when the account's owner turned that on for the profile —, and an adult's own key only when its owner chose to keep it on that device, otherwise in the tab's memory; a check sends only an image or a crop of the work, and only api stores learners' data on the server. Children use it under an adult's account, so it has no public profiles, contact between learners, geolocation, ads or external links, and it discloses that the tutor is an AI to every learner, with "report a problem" for the adult beside every reply of the tutor. Its signed build is hosted and deployed by infra and reads the deployment configuration at run time, so that self-hosting runs the same build. It belongs to stage 2, the first slice with learners, with tutor, canvas, api, skill-map and infra, and no child uses it before the parent's verifiable consent, the AI providers' contracts and the DPIA.

Its card in spec is the one in `spec/docs/architecture.md` whose heading names `app`. The card is the summary and this repository's [docs/architecture.md](docs/architecture.md) is the detail: it lists what the card left to decide, and the first epic of [RUN.md](RUN.md) decides it.

## Documents

The documents under `docs/` are in English, but for the epic archives `docs/plan/`, which stay in Russian; RUN.md and `run/` are in English, but for the bodies of tasks. Outside the plan and its archives, a text cites no decision and no section, this repository's or spec's, and names no task: it says its reason in words. Only a claim about the outside world cites its one record, `sources 1.1`, or spec's, `sources 2.3 spec`.

- [docs/README.md](docs/README.md) — for people: the index of the documents, with how to run app against a local api, how a release comes out and how to contribute; the README only says what the component is and where it stands.
- [docs/architecture.md](docs/architecture.md) — the component: what it does and does not do, its data and links, what is still to decide, and how it is built once that is decided.
- [docs/decisions.md](docs/decisions.md) — this repository's decision log: read it before proposing a change.
- [docs/sources.md](docs/sources.md) — the records of external facts — a provider's terms, a price, a law, a library's documentation — each with its source, its date and its quote; a claim in another document cites its one record, as `sources 1.1`. The results of a measurement are in [docs/measurements.md](docs/measurements.md), cited as `measurements 1`; [docs/architecture.md](docs/architecture.md) holds neither.
- [RUN.md](RUN.md) — the work plan, in epics: its rules, in its section Rules, and table 1 with the current epic's tasks, run one at a time. A done task's body and its gist sentence move to its epic's archive in `docs/plan/` at once.
- `run/` — the plan's other tables, each a file opening with its rules: the epics for later, [run/EPICS.md](run/EPICS.md); the questions to the author, [run/QUESTIONS.md](run/QUESTIONS.md); the technical debt, [run/DEBT.md](run/DEBT.md); the open tasks outside an epic, [run/TASKS.md](run/TASKS.md), of which a task reads only its own body. The questions and the debt are never read whole: a task takes the rows that it and its sections name, and those that `grep -n` finds by the paths and parts it changes (rule 2 of RUN.md).
- `spec/` — spec at `v0.19.12`, a git submodule and read-only here: the platform's vocabulary, formats, contracts, documents and decisions, and the rules imported below. Its documents are under `spec/docs/`. spec's own CLAUDE.md and AGENTS.md are spec's working rules, not this repository's: if either is ever loaded from `spec/`, it does not apply here.

## Environment

Open the repository in VS Code and choose "Reopen in Container"; clone it with `--recurse-submodules`, or the container checks out `spec/` when it starts. Keep the clone in a folder named `app`, as `git clone` names it: `.claude/settings.json` keeps spec's own CLAUDE.md and its rules, `spec/.claude/rules/`, out of this repository's sessions by that path. The container is spec's: Node.js, Go, buf and just, and the GitHub CLI and Claude Code on top. The tools of this repository's own code come with that code, at exact versions; how its container then differs from spec's is recorded as a decision. `just -f spec/justfile docs-check-repo` checks its documents: that its links lead somewhere, that the rule of citations holds — a record it cites of spec exists in spec/ at its tag —, that the decision log runs without gaps, and the tables of its RUN.md, and that its files, rules, decision entries, sections and rows keep within their budgets of size: spec's block `repository` of `spec/tools/docs-check/budgets.json`, with what [docs-budgets.json](docs-budgets.json) names in its place — raising one is an edit of that file. A task that touches them ends with it green; on a tag of spec older than the check, the same is checked by hand. When the repository has parts with checks of their own, each part's checks are its rule, `.claude/rules/<part>.md`, with the part's files in its `paths`, and this section names each rule and its part in one line: Claude Code loads a rule only when the session reads or edits a file it matches, and CI runs every check on every pull request (measurements 1.5 spec). `docs-check-repo` checks the rules too. It matches `paths` only against the files git lists, as CI has them, so a part whose files `.gitignore` keeps out of git — samples, synthetic data — has no rule: what must hold for it stays in this file, which every session loads, as a prohibition must anyway, since a rule loads only once the session has opened a file of its part.
