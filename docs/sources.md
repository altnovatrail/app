# app — sources

> The facts of the outside world the repository's documents under `docs/` rest on and no run of ours checks: a law, a regulator, a standard's normative text, a provider's terms and policies, a price, a license, a page that changes in place with no version, a text outside the repositories. Here are their records — the address, the date it was read and a quote in the source's language — and [architecture.md](architecture.md) and the decision log hold the claim and a citation of its one record by its number, `sources 1.1`, not a chain. A record's heading names its topic, not a task.
>
> No record is needed for a library's documentation or code at a version or commit — a link beside the claim —, for a behaviour a test or a measurement checks — they are its evidence —, or for spec's tags and the files of NovaTrail's and MathTrail's repositories — git, at a commit.
>
> A record is a subsection "N.M" of a topic: one source, or one reading of several sources for one decision. A record's number never changes and is never given again: a new one goes at the end of its topic, a new topic at the end of the file, and a record removed leaves a gap. A source read again with the same text changes the record's date; with another text, the claims and decisions on it are rewritten in the same change and the record holds the new reading alone — where a decision waits on the author, an open question, and both readings stand until it is closed. The model is `spec/docs/sources.md`. The results of measurements are not here but in [measurements.md](measurements.md).

## 1. How to keep it

- **What is a record.** The line is whether a run of ours checks the fact and whether its source has a version. A record holds what a legal reading rests on — a law, a regulator's guidance, a standard's normative text, terms, a policy, a price, a license, a brand's rules —, and any fact whose source changes in place with no version and which no run of ours checks: a service's limit, a design guideline, what only a device shows.
- **What is no record.** Another program's documentation or code at a version, a tag or a commit: a link where the claim stands, with no quote. A behaviour a test or a record of [measurements.md](measurements.md) checks: the test or the record is its evidence. spec's tags and the files of the other NovaTrail repositories and of MathTrail: git — a link to the repository at its commit, or the submodule.
- **A record** holds the address, the date of the page where it has one, the date read and the quote in the language of the source. What was not read in the primary source — a copy, a retelling, a page that did not open — the record names as such.
- **A reference.** A claim of a document cites its one record by its number: `(sources 5.1)`, and a record of spec as `sources 2.3 spec`, which holds the claim at the tag of the submodule, or the claim cites what holds it now.
- **What is not here:** the quotes that an entry of the decision log gives itself — they stay in the entry; the results of measurements — they are in [measurements.md](measurements.md).

### 3.1. Storage on the device

Read 2026-11-02. The quotes were checked with `curl` against the text of the pages:
- WHATWG, [Storage Standard](https://storage.spec.whatwg.org/), "Last Updated 19 October 2026": "The user agent cannot clear storage marked as persistent without involvement from the origin or user"; "A user agent that comes under storage pressure should clear network state and local storage buckets whose mode is "best-effort""; "Whenever a storage bucket is cleared by the user agent, it must be cleared in its entirety"; the quota "must not be a function of the available storage space on the device".
- MDN, [Storage quotas and eviction criteria](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria), "last modified on Jan 5, 2026":
  - Chromium — "an origin can store up to 60% of the total disk size in both persistent and best-effort modes"; Firefox without persistent storage — the smaller of "10% of the total disk size where the profile of the user is stored" and "10 GiB, which is the group limit"; Safari since macOS 14 and iOS 17 — "For WebKit-based browser apps, each origin can store up to around 60% of total disk";
  - "Browsers can store up to 5 MiB of local storage, and 5 MiB of session storage per origin"; beyond the quota a write "fails with a QuotaExceededError exception";
  - "In Firefox, when a site chooses to use persistent storage, the user is notified with a UI popup that their permission is requested. Safari and most Chromium-based browsers, such as Chrome or Edge, automatically approve or deny the request based on the user's history of interaction with the site and do not show any prompts to the user";
  - "If an origin has no user interaction, such as click or tap, in the last seven days of browser use, its data created from script will be deleted"; in private mode "stored data is usually deleted when the private browsing mode ends".
- WebKit, [Updates to Storage Policy](https://webkit.org/blog/14403/updates-to-storage-policy/), 2023-08-10: "For a browser app, the origin quota is up to 60% of the total disk space"; "Origin might be excluded from eviction if it has active page at the time of eviction, or its storage is in persistent mode"; `persist()` — "WebKit currently grants a request based on heuristics like whether the website is opened as a Home Screen Web App"; the HTTP cache is outside these rules: "Other types like cookies and HTTP cache are currently not subject to the policy below". [WebKit Features in Safari 17.0](https://webkit.org/blog/14445/webkit-features-in-safari-17-0/), 2023-09-18: "An origin is exempt from eviction when its storage mode is persistent".
- WebKit, [Full Third-Party Cookie Blocking and More](https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/), 2020-03-24: ITP erases "all of a website's script-writable storage after seven days of Safari use without user interaction on the site"; "Web applications added to the home screen are not part of Safari and thus have their own counter of days of use". [Tracking Prevention in WebKit](https://webkit.org/tracking-prevention/), changed 2023-04-27: "The first-party domain of home screen web applications is exempt from ITP's 7-day cap on all script-writeable storage"; "the website data of home screen web applications is kept isolated from Safari". - web.dev, [Storage for the web](https://web.dev/articles/storage-for-the-web), updated 2024-09-23: "In incognito mode, Chrome reduces the amount of storage an origin can use to approximately 5% of the total disk space"; with "Clear cookies and site data when you close all windows" — "a maximum of approximately 300MB". [Persistent storage](https://web.dev/articles/persistent-storage), updated 2020-05-12: in Chrome "if a site is considered important, the persistent storage permission is automatically granted, otherwise it is silently denied" — by engagement, by installation or a bookmark, and by the permission for notifications; "Firefox delegates the permission request to the user"; "Do not ask for persistent storage on page load".
- W3C, [Indexed Database API 3.0](https://w3c.github.io/IndexedDB/), Editor's Draft 30 October 2026: "Record values are stored and retrieved by value rather than by reference"; "Web applications are encouraged to use "relaxed" for ephemeral data such as caches or quickly changing records"; "The close event only fires if the connection closes abnormally, e.g. if the storage key's storage is cleared, or there is corruption or an I/O error"; "The blocked event fires if other clients still hold a connection to the database after their versionchange events have fired"; `"strict"` — "in cases where reducing the risk of data loss outweighs the impact to performance and power".
