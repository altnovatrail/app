# Журнал решений app

> Почему app устроен именно так. В каждой записи: что решено, почему, что отвергнуто и где это описано.
>
> **Правило:** не предлагать повторно отвергнутое без новых фактов. Если решение нужно поменять, спросить автора и обновить этот файл. Запись не переписывается: её правит поправка с датой в конце записи или заменяет новая запись, а старая остаётся на месте с пометкой «Заменено».
>
> Репозиторий заведён 2026-10-19 из заготовки `spec` v0.1.0 (R21 spec), 2026-10-20 перешёл на `spec` v0.2.9 (R01), а 2026-11-02 — на v0.6.2 (R02). Чем он со временем отличается от заготовки — инструментами в devcontainer, правилами в RUN.md, — записывается здесь решением, как R46 canvas-api записал отличия от своего образца. Следующий номер — R04.
>
> Здесь записи цитируются как `R03`, в других репозиториях — как `R03 app`. Решения `spec` цитируются как «R18 spec», решения MathTrail — как «R37 canvas-api», а списком — «canvas-api: R37, R38». У каждого журнала свои номера.

## Фреймворк и сборка

**R03. `app` пишется на React 19 и собирается Vite 8. Типы проверяет TypeScript 7, формат и линт — Biome, тесты — Vitest в Node и в Chromium. CSS сжимает esbuild, иконки вшивает `unplugin-icons`, а пакеты ставит npm, который идёт с Node.** Ответы автора 2026-11-02 при планировании T01. Версии, лицензии и правила конфигурации — [architecture.md](architecture.md), раздел 3.1, а источники — раздел 4.
- **Фреймворк — React 19.3.1.** Элемент `<novatrail-canvas>` получает данные свойствами, а React 19 «passes all tests on Custom Elements Everywhere» и присваивает как свойство то, что есть у класса элемента. Для потребителя на React 19 `canvas` уже записал, как с элементом быть: свойства идут в порядке JSX, события — в нижнем регистре, новый элемент на звено урока — новым `key`, точка входа — до первой отрисовки (R42 canvas). Тот же выбор — у canvas-api (R47 canvas-api).
- **Сборщик — Vite 8.3.5 с `@vitejs/plugin-react` 6.1.2**, без Babel. CSS сжимает esbuild 0.28.2: `build.cssMinify: 'esbuild'`. `lightningcss` 1.33.0 под MPL-2.0 Vite 8 ставит обязательной зависимостью и по умолчанию сжимает им CSS. С esbuild он остаётся в lock-файле, но ничего из поставки не обрабатывает: это инструмент разработки, который никуда не поставляется и своего кода не вносит, — названное исключение `dev` в `licenses.json`, с причиной, как R14 canvas (R12 spec, R39 spec).
- **Типы — TypeScript 7.0.2**, как у `canvas` и `spec` (R73 spec): `tsc --noEmit` проверяет, а собирает Vite.
- **Формат и линт — Biome 2.6.4.** typescript-eslint 8.72.1 требует `typescript` ниже 6.1, а у TypeScript 7 API нет; ESLint 9 снят с поддержки 2026-08-06. Biome один делает формат и линт и обходится без TypeScript — так решили и `canvas`, и canvas-api (R12 canvas, R47 canvas-api).
- **Тесты — Vitest 5.0.5.** Логика — в Node, экраны с настоящим элементом канвы — в Chromium, провайдером `@vitest/browser-playwright` с `headless: true`. Экраны отрисовывает Testing Library для React, а ввод ведёт `userEvent` из `vitest/browser` — через Chrome DevTools Protocol, а не подделкой событий. Покрытие — `@vitest/coverage-v8`, отчёт `coverage/lcov.info` для `codecov/patch` (R48 spec). Браузер — Chrome Headless Shell из образа Playwright по тегу и дайджесту, как R13 canvas: сборка Google Chrome for Testing на бесплатных условиях Google — названное исключение, в двух границах поправки 2026-10-22 к R12 spec: NovaTrail его не распространяет и собирается, запускается и разворачивается без него (Д16 в таблице 4 RUN.md `spec`). В эмуляторах DOM элемент канвы не работает: happy-dom без адаптера отдаёт из `getContext()` `null`, а jsdom без пакета `canvas` рисует `<canvas>` как `<div>`.
- **Иконки — `unplugin-icons` 24.0.0** с `compiler: 'jsx'` и `jsx: 'react'`, через `@svgr/core` и `@svgr/plugin-jsx` 8.1.0. При сборке он вшивает только те иконки, что берёт приложение, из пакета набора `@iconify-json/<префикс>` по точной версии; `autoInstall` выключен. Компонентов Iconify, которые грузят иконки у API Iconify во время работы, в приложении нет. Набор выбирает T47 `spec`.
- **Пакеты ставит npm** из Node 24.21.0 devcontainer: `licenses-check-repo` читает только lock-файл npm (R39 spec), а сам npm назван исключением в `spec` (поправка 2026-10-22 к R12 spec). В `.npmrc` — `save-exact=true` и `ignore-scripts=true`, как требует обёртка TypeScript `.github`.
- **Версии** сторонних пакетов — последние из вышедших не позже чем за три дня до установки, как в R12 canvas. Раздел 3.1 называет их на 2026-11-02, а первая задача кода ставит их тем же правилом и собирает lock-файл `npm install --before=…`. Пакеты `@altnovatrail` под паузу не подпадают: `@altnovatrail/spec` — той же версии, что тег подмодуля, и выходит в день тега (R73 spec), а подпись их всех сверяет `release-verify-npm` (R77 spec).

— *Почему:* ответы автора 2026-11-02 при планировании T01, все — по рекомендациям плана (RUN.md, T01, «Решено автором»). TypeScript 7, Biome и npm — не выбор: их задают `spec`, обёртка TypeScript `.github` и сам TypeScript 7. Набор инструментов тот же, что у `canvas`, и у обоих один договор обёртки и одна стадия с браузером.

— *Отвергнуто:*
- Preact 11: 11.0.0 вышел 2026-09-30, Custom Elements Everywhere проверял только Preact 10, а `@preact/preset-vite` 2.10.6 требует Babel и тестировался на Preact 10. Preact 10.29.8 — прошлая мажорная версия;
- Lit 3.3.3 — библиотека компонентов, а не фреймворк приложения: состояние, маршруты и тесты экранов пришлось бы собирать самим. Vue, Svelte и Solid — правил для них у `canvas` нет, а Svelte 5 Custom Elements Everywhere не проверял;
- ESLint 10 с typescript-eslint и Prettier — по причине выше;
- только happy-dom с заглушкой канвы: порядок свойств, события и `exportWork()` проверялись бы на заглушке. happy-dom для экранов и отдельный набор в браузере: браузер и исключение нужны всё равно, а проектов Vitest больше;
- провайдер WebdriverIO — он сам скачивает браузер во время прогона, а `canvas` берёт его из образа по дайджесту (R13 canvas); провайдер `preview` «relies on simulating events»; `@testing-library/user-event` — по той же причине: он подделывает события в JavaScript;

- `unplugin-icons` с сырым SVG — разметка вставлялась бы строкой; компоненты Iconify во время работы — запрос с устройства ученика к API Iconify (T47 в RUN.md `spec`);
